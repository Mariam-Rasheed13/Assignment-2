Project Structure
The project was created using Express Generator with the EJS view engine. The project files are organized into folders so that the server-side code, routes, website pages, and public assets are kept separate.

The main project structure is:
WebProject
- bin
    - www: Starts the Express application and creates the HTTP server.

- public
    - images
        - mariam.jpg: My personal picture displayed on the About Me page.

    - javascripts
        - bootstrap
            - bootstrap.bundle.min.js: Bootstrap JavaScript bundle.

    - stylesheets
        - bootstrap
            - bootstrap.min.css: Bootstrap stylesheet.

        - fontawesome
            - all.min.css: Font Awesome Free stylesheet.

        - style.css: My custom CSS stylesheet.

    - webfonts
        - fa-brands-400.woff2
        - fa-regular-400.woff2
        - fa-solid-900.woff2
        - fa-v4compatibility.woff2

These files contain the font files required to display Font Awesome icons.

- routes
    - index.js: Contains the routes for the Home, About Me, Projects, and Contact Me pages, as well as the contact form POST route.
    - users.js: Contains the default example users route generated by Express Generator.

- views
    - about.ejs: Contains the About Me page.
    - contact.ejs: Contains the Contact Me page and form.
    - error.ejs: Displays application error information.
    - index.ejs: Contains the Home page.
    - layout.ejs: Contains the shared website layout, including the header, navigation bar, and footer.
    - projects.ejs: Contains the Projects page.

- .gitignore: Specifies which files and folders Git should ignore.
- app.js: The main Express application file that configures the application, middleware, routes, EJS, and error handling.
- package.json: Contains project information, the start script, and required dependencies.
- package-lock.json: Records the installed dependency versions.
- node_modules: Contains the packages and dependencies installed for the project using npm.

The node_modules folder is automatically generated when running npm install. It does not need to be manually maintained or committed to GitHub.

Description of the Main Files and Folders

bin/www
This file starts the Express application and creates the HTTP server. It determines which port the application should use. It uses the port provided by the hosting service through process.env.PORT, or port 3000 when running locally. This allows the application to run both on my computer and on Render.

app.js
This is the main Express application file. It imports the required packages, configures the application, and connects the different parts of the website.
It sets the views folder and configures EJS as the view engine. It also uses express-ejs-layouts to provide a shared layout across the website pages.
The file includes middleware for logging requests with Morgan, processing JSON data, processing form submissions, handling cookies, and serving static files from the public folder. It also connects the main routes and users routes and includes error handling for pages that cannot be found or other application errors.

package.json
This file contains the project information, the start script, and the dependencies required to run the website. Some of the main dependencies include Express, EJS, express-ejs-layouts, Bootstrap, and Font Awesome Free.
The start script runs the application using node ./bin/www.

package-lock.json
This file records the installed dependency versions. It helps keep the dependencies consistent when the project is installed on another computer or deployed to a hosting service.

.gitignore
This file specifies which files and folders Git should ignore when tracking the project. It helps prevent unnecessary generated files, such as installed dependencies, from being included in the GitHub repository.

routes/index.js
This file contains the main website routes. It defines the GET routes for the Home, About Me, Projects, and Contact Me pages. It also contains the POST route that handles the contact form submission.
Each page is displayed using res.render(), which tells Express which EJS file to display and passes the page title to the view.

routes/users.js
This file was included when the project was generated using Express Generator. It contains the default example users route. The main portfolio pages are handled separately in routes/index.js.

views/
This folder contains the EJS templates used to display the website. It includes the four main pages, the shared layout, and the error page. Using .ejs files allows the website to combine HTML with dynamic values and EJS template logic.

public/
This folder contains the static files used by the website, including images, stylesheets, JavaScript files, and Font Awesome webfont files. These files are served by Express so that the browser can load the website’s styling, images, and icons.

public/images/mariam.jpg
This is the personal picture displayed on the About Me page.

public/stylesheets/style.css
This is my custom CSS file. It controls the website’s colours, gradients, fonts, spacing, borders, rounded corners, shadows, hover effects, and responsive styling.

public/stylesheets/bootstrap/
This folder contains the Bootstrap CSS file used to apply Bootstrap styling and layout classes.

public/javascripts/bootstrap/
This folder contains the Bootstrap JavaScript bundle used by the website.

public/stylesheets/fontawesome/ and public/webfonts/
These folders contain the Font Awesome Free stylesheet and the font files required to display the icons correctly.

EJS Templating and Shared Layout
I used EJS as the templating engine for the website. EJS allows HTML pages to include dynamic information and template logic.
Instead of repeating the same header, navigation bar, and footer in every page, I created a shared layout in views/layout.ejs.
The layout contains the main HTML document structure, including:
-HTML5 document declaration.
-Language set to English.
-Character encoding set to UTF-8.
-Responsive viewport settings.
-Dynamic page title.
-Bootstrap CSS.
-Font Awesome CSS.
-My custom CSS stylesheet.
-Website header and navigation bar.
-Main content area.
-Website footer.
-Bootstrap JavaScript bundle.
The layout uses the page title passed from routes/index.js to display the correct browser title. It also uses EJS conditions to identify which navigation link should be shown as active.
The main content from each individual EJS page is inserted into the shared layout using <%- body %>. This means that the same header, navigation bar, and footer appear on every page without having to write the same code multiple times.
I also used EJS conditional logic on the Contact Me page to check whether the form has been submitted. If the submitted value is present, the success message is displayed.
This makes the website easier to organize and maintain because changes to the shared layout can be made in one file instead of editing every individual page.

Express Routes
I created the main website routes in routes/index.js. Each route uses res.render() to display the appropriate EJS page.
The routes are:
-GET / displays index.ejs, which is the Home page.
-GET /about displays about.ejs, which is the About Me page.
-GET /projects displays projects.ejs, which is the Projects page.
-GET /contact displays contact.ejs, which is the Contact Me page.
-POST /contact handles the contact form submission and displays the success message.
The GET routes allow visitors to navigate between the different pages. The POST route is used when the visitor submits the contact form.
I also configured Express in app.js to process URL-encoded form data so that form submissions can be handled by the application.

The form also has styling for its input fields, focus states, verification checkbox, reset button, and submit button. The input fields have rounded corners and change their border and shadow when selected.

Bootstrap and Responsive Layout

I included Bootstrap to help organize the website layout and make it responsive on different screen sizes.

Bootstrap is included locally in the project through its CSS and JavaScript files.

I used Bootstrap classes such as containers, rows, columns, and navigation classes to organize the content. For example, the About Me page uses a Bootstrap row with two columns to display the introduction and personal picture beside each other on larger screens.

The Bootstrap grid allows the columns to adjust depending on the available screen width. This helps the page remain organized on smaller devices.

I also used responsive CSS media queries in my custom stylesheet to adjust the spacing and layout for different screen sizes.

The stylesheet includes:
-Laptop screens: Minimum width of 960px.
-Tablet screens: Width between 481px and 959px.
-Phone screens: Maximum width of 480px.

For tablet screens, I adjusted the main content padding and section spacing so that the content fits comfortably.

For phone screens, I reduced the spacing around the main content, adjusted the navigation links, reduced the Home page heading size, and changed the footer links so that they display vertically.

These changes help prevent the content from appearing too crowded on smaller screens.
